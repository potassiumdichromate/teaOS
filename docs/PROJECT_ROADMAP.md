## Open — real, prioritized

1. **bcryptjs blocks the event loop under concurrent login load** (found by this session's load test — see docs/THREAT_MODEL.md T9). Fix: swap to the native `bcrypt` binding (offloads to libuv's thread pool) or move hashing off the request path. Highest-priority open item because it's a measured, real production-readiness gap, not a theoretical one.
2. **No rate limiting** on `/auth/login` or public `/verify` (docs/THREAT_MODEL.md T5, T6).
3. ~~**`apps/web` has no production API base URL mechanism**~~ — **fixed 2026-07-29.** New `lib/origin.ts` reads `VITE_API_BASE_URL` for both REST and WebSocket calls, falling back to the old relative-path behavior when unset. Real Vercel (`apps/web/vercel.json`) and Render (`render.yaml`, repo root) deployment configs now exist and wire this up end to end — see docs/DEPLOYMENT.md's "Deploying to Vercel + Render" section.
4. **No CI pipeline, no Dockerfiles** (docs/DEPLOYMENT.md) — `build`/`test`/`typecheck` are all real scriptable checks today; none run automatically on push yet. Partially addressed: `render.yaml` and `apps/web/vercel.json` are real infra-as-code for the deploy targets themselves, but there's still no pipeline that runs `npm test` before a deploy goes live, and no preview-deployment CORS handling for Vercel's per-PR URLs.
